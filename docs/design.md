# CMT 設計ドラフト v0.1

状態: ドラフト（議論の整理。未検証の仮説を含む）

## 1. 目的

- 設計の揺れ（概念の混同）を排除する。
- 重みに頼らない長期記憶を持つ。概念の変更が、変更した事実とともに残る。

## 2. 現行モデルの診断

現行のLLMには設計された概念層がない。概念に相当する表現は中間層に自然発生しているが、次の点が欠けている。

| 機構 | 現行モデルの実態 |
|---|---|
| 分化と精緻化 | 学習中には起きる。学習後は重みが固定され、推論時は文脈内の一時的な調整しかできない |
| 発達系譜の記憶 | ない。重みは現在の状態だけを持ち、分化の履歴は残らない |
| 言語との対応 | 暗黙には存在する。連続的で文脈に依存し、番地を指定できず、同一性の基準がない |
| 概念の確定 | ない。どの概念を指すかを決める工程がなく、重ね合わせた状態がそのまま語になる |

固定した概念語彙をモデルに埋め込む過去の試み（概念ボトルネック、知識グラフ統合など）は、語彙が対象を覆えない、情報が名前付き経路を迂回する、性能が落ちる、という理由で主流にならなかった。本設計は概念体系を固定せず、変更が多発する前提に立つ点でこれらと異なる。

## 3. 設計原則

1. **正本は記号的で、モデル本体の外にある。** 概念式と型付きグラフが正本。重みや記憶ベクトルはそこからコンパイルした派生物で、いつでも再生成できる。
2. **本体の重みは固定する。** 本体は言語能力と、概念記憶を読む能力だけを担う。
3. **接続点を深くする。** 概念体系は部品としては外周にあるが、モデルへの接続は入力（文章）から中間層、重みへと深めていく。
4. **変更は追記する。** 上書きしない。すべての変更は版・理由・取り消し手段を持つ。
5. **効果は検証で確かめる。** 接続が効いたかどうかは、差異ごとのテストで測る。

## 4. 全体構成

```
人間 ⇄ [意図の解釈] → 概念式 → [用語サーバー] → [型付きグラフ = 正本]
                                                        │
                                                   [カーネル]
                                          変更記録の保持とコンパイル
                                                        │
                    ┌───────────────┬───────────────────┼────────────────┐
                 C0 入力         C1 中間層           C2 重み          C3 出力
               定義文の注入    概念記憶の注入     差分重みの加算    概念の確定と検証
                    └───────────────┴─────────┬─────────┴────────────────┘
                                       [本体モデル（固定）]
                                              │
                                  実装・テスト → [検証] → グラフへ差し戻し
```

## 5. 構成要素

### 5.1 概念式

制御自然言語で書く。実験用の最小形は次のとおり。

- 概念 = 根（上位概念）＋ 修飾の集合。修飾は「役割: 値」の組で、値は概念の識別子。
- 正規形 = 役割名で整列した修飾の集合。正規形が一致すれば同一の概念。
- 表示用の語（ラベル）は正規形とは別に持つ。同音異義は許さない。
- 抽象概念は修飾を持たず、上位概念として置く。

```
確定注文 = 注文 + {状態: 確定済み}
仮注文   = 注文 + {状態: 未確定}
```

### 5.2 用語サーバー

- 語 → 概念の識別子の解決。
- 概念式の正規化と同一性の判定。
- 置換された概念への参照を、現行の概念へ案内する。

### 5.3 型付きグラフ（正本）

- ノード: 概念、役割。
- 関係: 修飾、分化元、精緻化元、置換先、版。
- 変更記録: 追記専用。各変更は「種類（新設・分化・精緻化・置換・役割追加）、対象、理由、合意者、時刻」を持つ。

### 5.4 カーネル

状態を持たない本体モデルの外側で、状態を持ち続ける中核。

- 変更記録を保持する。
- 変更記録を、接続層が使える形（定義文、概念ベクトル、差分重み）にコンパイルする。
- 二段構えで運用する。新しく不安定な変更は C0・C1 で保持し、安定した変更を定期的に C2 へ固定する。
- コンパイル結果は派生物。本体モデルを入れ替えたら正本から作り直す。

### 5.5 接続層

| 記号 | 接続先 | 方式 | 想定される弱点 |
|---|---|---|---|
| C0 | 入力 | 関連する概念の定義と系譜を文章として渡す | 本体の重みにある元の意味に押し負ける（仮説。E1で測る） |
| C1 | 中間層 | 概念の識別子で引くベクトルを、中間層の活性化に加える。子 = 親 + 差分 の形で持つ | 概念の単位がモデル内で定まっていない |
| C2 | 重み | 1つの変更を1つの小さな差分重み（低ランクのアダプタ）にする。合成は加算、取り消しは除去 | 数が増えると干渉する |
| C3 | 出力 | 語を出す前に概念の識別子を確定させる。出力後に語彙を検査する | 内部の表現は変えない |

C1 の概念ベクトルの作り方は3案あり、実験で比べる。

1. 疎な辞書学習（SAE）の特徴量の方向を使う。
2. 兄弟概念の定義文を読ませたときの活性化の差を使う。
3. 本体を固定したまま、概念ごとのベクトルを学習する。

### 5.6 検証

- 生成前: 語が現行の概念に解決できるか。
- 生成後: 語彙リント。
- 分化の条件: 兄弟概念では失敗し、その概念では通るテストが存在すること（差異とテストの1対1対応）。

## 6. 実験計画

### 6.1 題材

実験は日本語で行う。日本語での概念の混同が、概念管理によって解消されるかを見ることが目的の一部である。

本体モデルの元の意味と**衝突する**小さな概念体系を作る。衝突がないと、接続が効いたのか元から知っていたのかを区別できない。

- 一般的な語を、プロジェクト固有の意味に再定義したもの。
- 1つの語を2つの兄弟概念に分化したもの。
- 概念を別の概念に置換したもの。

### 6.2 測るもの

| 指標 | 内容 |
|---|---|
| 定義への追従 | プロジェクトの定義に沿う答えと、元の意味に沿う答えの、確率の差 |
| 兄弟の区別 | 兄弟概念を取り違えない率 |
| 局所性 | 無関係な質問への出力が変わらないこと |
| 取り消し | 変更を外したとき、変更前の出力に戻ること |
| 波及 | 変更から導かれる帰結に正しく答えること |
| 規模 | 変更数を 1、10、100 と増やしたときの上記の劣化 |

### 6.3 段階

| 段階 | 内容 | 確かめる問い |
|---|---|---|
| E0 | モデルの読み込み、中間層の読み書きの仕組み、題材と指標の実装 | 基線の値 |
| E1 | C0（定義文の注入）だけで測る。定義の長さ、定義から質問までの距離、元の意味の強さを変える | 文章での注入は本当に元の意味に押し負けるか |
| E2 | 題材の概念に対応する特徴量を SAE で探す。辞書の大きさを変えて特徴量の分裂を追う。日本語と英語で同じ特徴量が働くかを見る | モデル内に、接続先にできる概念の単位があるか |
| E3 | C1（中間層への注入）を実装し、E1 と同じ指標で比べる。親 + 差分 の合成が成り立つかを見る | 中間層への接続は入力への接続より効くか |
| E4 | C2（変更ごとの差分重み）を実装する。合成、取り消し、干渉を測る | 変更記録を重みとして扱えるか |
| E5 | 二段構え（C0・C1 で保持 → C2 へ固定）を通しで動かす | 固定の前後で振る舞いが保たれるか |
| E6 | C3（概念の確定）を加える | 確定の工程で揺れが減るか |

E1 の結果が「押し負けない」なら、C1 以降の必要性を見直す。E2 の結果が「単位がない」なら、C1 は案3（学習するベクトル）に寄せる。

## 7. モデルの選定

| モデル | 規模 | 利点 | 注意点 |
|---|---|---|---|
| Gemma 2 2B | 約26億 | 全層の SAE（Gemma Scope）が辞書の大きさ違いで公開されている。E2 に最も合う | 利用規約への同意が必要。CPU では遅い |
| Qwen2.5 0.5B / 1.5B | 約5億 / 15億 | Apache 2.0。同意手続きが不要。日本語が比較的通る | 公開されている SAE が少ない |
| GPT-2 small | 約1.2億 | 最も研究されており、解釈用の道具が揃う。CPU で速い | 日本語がほぼ使えない。能力が低い |

推奨は次の2本立て。

- **主対象: Gemma 2 2B。** SAE が揃っており、特徴量の分裂を系譜として観察できる。
- **仕組みの動作確認: Qwen2.5 0.5B。** 手続きなしで取得でき、CPU で回る。

現在の実行環境は CPU 4コア、メモリ 15GB、GPU なし。E0・E1 と小規模な E3 は動く。Gemma 2 2B を使う E2 以降と、E4 の学習は GPU のある環境が望ましい。

## 8. 安全上の取り決め

- 重みは公式の配布元から、safetensors 形式だけを取得する。版を固定する。
- モデル付属のコードは実行しない（`trust_remote_code` を使わない）。
- 本体の重みは書き換えない。変更はすべて外付けの差分で、除去できる。
- 実験はローカルで完結させる。

## 9. 未決事項

1. **役割が増えたときの同一性。** 既存の概念は新しい役割について「未指定」か「既定値を持つ」か。
2. **概念の単位。** モデル内の特徴量の粒度は解析側の設定で変わる。外部の概念の識別子を、モデル内の何に結びつけるか。
3. **識別子の安定性。** 精緻化で正規形が変わったとき、識別子を引き継ぐか。
4. **干渉。** 差分重みや概念ベクトルが多数になったときの上限。
5. **波及。** 1つの変更が関連概念に正しく伝わるか。グラフから波及範囲を出し、そこを学習と検証の対象にする案がある。
6. **名詞以外の概念。** イベント、状態遷移、制約の概念式。
7. **小型モデルの日本語能力。** 題材を日本語で書くか、英語で書くか。

## 10. 実験から得た設計変更（暫定）

Qwen2.5-1.5B-Instruct、24概念での結果に基づく。数値と詳細は `experiments/README.md`。

1. **正本は「定義＋境界を示す適用例」の組になる。** 定義文だけから作った概念ベクトルは、定義を暗唱できても適用に効かなかった。適用例を教師にして初めて境界が移った。適用例は検証層のテストと同じものなので、テストは「生成後に確かめるもの」から「概念を成立させる材料」に変わる。学習用と検証用の2組が要る。
2. **用語集を文脈に載せる方式は成り立たない。** 全定義を渡すと、再定義は定義なしとほぼ同じ正答率に落ちる。用語サーバーは、問い合わせごとに関係する概念だけを選んで渡す。
3. **一般語を再定義しても、再定義に従わせることが解くべき課題である。** 一般語に別の意味を与えると、定義を直前に置いても元の意味に負ける（0.58）。新しく作った語なら文章だけで従う（1.00）。再定義を避ける命名規則は回避策にすぎず、目標ではない。設計の語彙は一般語を使うのが普通で、避けきれない。現時点で再定義に従わせられた手段は概念ベクトル（0.79）だけで、まだ不十分である。再定義への追従率を、本設計の主要な指標とする。
   - 注意: 語を、元の語が見えない新しい語に改名しても追従率は 0.58 のまま変わらなかった（E5）。失敗の原因は、語が元から持つ意味との衝突だけではなく、定義を事例に当てはめる推論の誤りを含む。小さいモデルの推論力の不足と、元の意味との衝突とは、まだ切り分けられていない。
4. **用語サーバーは実行時の束縛も担う。** 概念ベクトルは、入力のどの位置がどの概念の語かが分かって初めて加えられる。語の境界の判定（「会社員」の中の「社員」）もここの責任になる。1つの概念を文章とベクトルのどちらで渡すかの振り分けも要る（併用すると下がる）。
5. **固定先は中間層のベクトルで足りる可能性がある。** 1概念1本で済み、外せば元に戻り、24概念を同時に入れても干渉がほぼない。差分重み（C2）は、規模を増やして干渉が出たときの次の手に下がる。
6. **判定はベクトル、説明は文章。** ベクトルは判定を動かすが、理由を説明する力は与えない。説明が要る用途では文章での定義が要る。
7. **シンボルの選定は記号側が担う。** 概念とシンボルの対応は型付きグラフの関係として厳密に持て、参照の解決も機械的に検査できる。ベクトルは「いま扱っている事例はどの概念か」という解釈の揃えに限る（未検証）。

適用できる条件: 概念ベクトルは、重みが公開されていて自前で動かせるモデルでしか使えない。API 経由でしか使えないモデルでは、文章の側で再定義に従わせる手段（言い換えなど）を見つける必要がある。

### 再定義の捉え方と、成功の基準

概念を「語に対応する表現」ではなく「その語を使うときに走る推論」と捉える。一般語の再定義とは、その語のあらゆる使い方が共有している推論の内容を変えることである。

語の使い方には少なくとも3つある。

| 使い方 | 内容 |
|---|---|
| 定義する | 定義文を述べる |
| 適用する | 事例がその概念に当たるかを判定する |
| 説明する | 判定の理由を述べる |

出力が変わったことは、推論が変わったことの証拠にならない。定義文だけで学習したベクトルは、定義文の出力を変えたが、適用は変えなかった。適用例で学習したベクトルは、適用を変えたが、説明は変えなかった。どちらも1つの使い方を変えただけである。

**再定義が成功したと言える基準は、1つの使い方で教えたときに、他の使い方も揃って変わることである。** これを本設計の主要な指標とする（3項の「再定義への追従率」を置き換える）。揃って変わる書き込み位置がモデルの中にあるかどうかが、モデル側を変える方向の成否を決める。

## 11. 実験の進捗と残り

### 済んだもの

| 記号 | 内容 | 結果の要点 |
|---|---|---|
| E1 | 定義を文章として注入 | 再定義は直前に置いても 0.58。用語集に埋めると 0.42（定義なし 0.38） |
| E1b | 適用例を文章として注入 | 定義＋適用例4問で、衝突 0.79、非衝突 0.71 |
| E3（定義のみ） | 定義の暗唱で概念ベクトルを学習 | 適用に効かない。答えが反転するだけ |
| E3（適用例） | 適用例で概念ベクトルを学習 | 未見の設問で、衝突 0.79、非衝突 0.92 |
| E3b | 転移・干渉・局所性 | 衝突への効果は3形式とも 0.79。24概念同時でも劣化は最大 0.04 |
| E3c | 文章を生成させたときの答え | 衝突 0.67、非衝突 0.88。理由の説明はできない |
| E4 | 修飾の合成 | 結論なし。3組中2組で学習が収束せず。収束した1組は未学習の上位概念で 0.88 |
| E5 | 言い換え（改名、定義の展開） | 改名しても衝突 0.58 のまま。E1 の失敗は語の意味の衝突だけでは説明できない |

### 残り（この順に進める）

1. **より大きいモデルでの E1 と E5。**（実行中）定義文だけで従えるようになるか、改名の効果が現れるか。
2. **E6 使い方をまたぐ転移。** 定義文で学習したベクトルと適用例で学習したベクトルについて、「定義する」側（定義の二択、定義文の出しやすさ）を測り、「適用する」側の結果と並べる。続けて、定義と適用の両方を教師にして学習し、両方が揃って変わるかを見る。
3. **層の選択。** 浅い層から中央の層まで変えて、使い方が揃って変わる位置を探す。
4. **途中経過を書かせる切り分け。** 定義の条件と事例の照合を先に書かせてから答えさせ、文章での失敗が「一度の計算で済ませる制約」によるものかを見る。
5. **説明の測定。** 判定の理由が定義に沿っているかを数値化する方法を作る。
6. **E4 のやり直し。** 学習の反復回数と学習率を見直し、収束しなかった2組をやり直す。
3. **併用の問題の切り分け。** 定義文の中の語にはベクトルを加えない形にして、文章とベクトルが両立するかを見る。
4. **シンボルの選定。** コードを書かせ、概念に対応する既存シンボルを参照する率を、文章とベクトルで比べる。シンボルの位置にベクトルを加えたときにコードが壊れないかも見る。
5. **日本語の弱さの測定。** 文章を生成させ、廃止された語の使用や兄弟概念の取り違えを検査する。二択では弱さが出なかった。
7. **系譜の操作。** 定義を改めたときの再学習（旧版のベクトルを初期値にする）、取り消し、置換をベクトルの側で試す。
8. **差分重み（C2）との比較。** 同じ教師で低ランクのアダプタを学習し、効果・干渉・取り消しを比べる。
9. **より大きいモデルでの E3。** 概念ベクトルの効果が、大きいモデルでも現れるか。
10. **規模。** 概念数を増やして干渉を測る。
11. **数値の境界を持つ概念。** ベクトルで学習しきれなかった原因の切り分け。
12. **E2 概念の単位の観測。** 疎な辞書を自前で学習し、特徴量の分裂を系譜として観察する。

### 未決事項

9節の項目はすべて未決のまま。実験はまだ同一性・役割の追加・識別子の安定性には触れていない。
