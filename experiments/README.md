## E1: 定義を文章として注入したときの追従

```
python e1_context_injection.py --model Qwen/Qwen2.5-1.5B-Instruct
```

- 題材: `data/concepts_ja.json`（日本語、79問、二択）
- 結果: `results/e1_<モデル名>.json`

### 条件

| 条件 | 内容 |
|---|---|
| none | 定義なし |
| near | 設問に関係する定義だけを設問の直前に置く |
| glossary | 全55定義（1445トークン）を用語集としてシステムプロンプトに置く |
| far-N | 用語集のあとに無関係な文章を約Nトークン挟む |

### 結果（Qwen2.5-1.5B-Instruct、正答率）

選択肢の順序を入れ替えた2回の平均で判定した値。

| 群 | 内容 | 問数 | none | near | glossary | far-500 | far-2000 |
|---|---|---|---|---|---|---|---|
| G1 | 一般の類義語・同音語 | 19 | 1.00 | 0.95 | 1.00 | 1.00 | 1.00 |
| G2c | 一般語の再定義。定義が元の意味と衝突する設問 | 24 | 0.38 | 0.58 | 0.42 | 0.42 | 0.42 |
| G2k | 同じ再定義で、定義と元の意味が一致する設問 | 24 | 0.75 | 0.75 | 0.83 | 0.83 | 0.88 |
| G3 | 分化した兄弟概念 | 8 | 0.38 | 1.00 | 0.75 | 0.62 | 0.62 |
| G4 | 置換された用語 | 4 | 0.25 | 1.00 | 0.75 | 0.75 | 0.75 |

### 読み取れること

- **再定義で元の意味と衝突する設問（G2c）は、定義を直前に置いても 0.58 にとどまる。** 用語集に埋めると 0.42 で、定義なし（0.38）とほぼ変わらない。
- **衝突しない設問（G2k）は定義の有無にかかわらず 0.75 以上。** G2c の低さは、設問形式の難しさではなく衝突によるものと読める。
- **分化と置換（G3・G4）は、定義が直前にあれば従う。用語集に埋めると落ちる。**
- **距離の影響は小さい。** 落ちる原因は、無関係な文章との距離より、多数の定義の中に埋まることにある。
- **G1 は定義なしで満点。** この形式では弱さを測れていない。

### 限界

- 問数が少ない（群あたり4〜24問）。傾向の確認にとどまる。
- 0.5B モデルは選択肢の位置への偏りが強く、結果を解釈できない（`results/e1_Qwen2.5-0.5B-Instruct.json`）。
- モデルが小さい。定義を読んで適用する力そのものが不足している可能性があり、より大きいモデルでの確認が要る。
- 二択の1トークンだけを見ている。文章を生成させたときの語の使い分けは測っていない。

## E3: 定義を中間層のベクトルへコンパイルする

```
python e3_concept_vectors.py --model Qwen/Qwen2.5-1.5B-Instruct --layer 8 --objective def
```

- 本体の重みは固定。概念ごとに1本のベクトルを持ち、入力中でその語が現れた位置で、第8層の出力に加える。
- `--objective def`: 定義文を暗唱できるようにベクトルを学習する（教師は定義文だけ）。
- `--objective qa`: 適用例の二択（`data/train_qa_ja.json`、概念あたり4問。評価の設問とは別の事例）で学習する。

### 結果: 定義文だけで学習（Qwen2.5-1.5B-Instruct、第8層、24概念）

| 群 | 問数 | none | vec（ベクトルだけ） | near（定義文だけ） | near+vec |
|---|---|---|---|---|---|
| G2c 衝突する設問 | 24 | 0.38 | 0.67 | 0.58 | 0.67 |
| G2k 衝突しない設問 | 24 | 0.75 | 0.33 | 0.75 | 0.25 |

- 学習の損失は全概念で 0.01 前後まで下がる。定義の暗唱は覚える。
- 衝突する設問は上がるが、衝突しない設問が同じだけ下がる。両群を合わせると 0.50 で、偶然と同じ。
- 選択肢の順序を入れ替えても両方正答する率は、ほぼ 0 まで落ちる。
- つまり、このベクトルは概念の境界を移していない。語の表現を壊し、答えを反転させているだけである。**定義の暗唱を教師にしたコンパイルは、適用に波及しない。**

### 結果: 適用例で学習（Qwen2.5-1.5B-Instruct、第8層、24概念）

教師は概念あたり4問の適用例。評価の設問は学習に使っていない別の事例。文章側の対照として、同じ4問を文脈に置いた場合も測った（`e1b_examples_in_context.py`）。

| 条件 | G2c 衝突する設問 | G2k 衝突しない設問 | 両方に正答した概念数 |
|---|---|---|---|
| 何もなし | 0.38 | 0.75 | 5 / 24 |
| 定義文を文脈に置く | 0.58 | 0.75 | 10 / 24 |
| 適用例4問を文脈に置く | 0.67 | 0.75 | 10 / 24 |
| 定義文と適用例4問を文脈に置く | 0.79 | 0.71 | 12 / 24 |
| **ベクトルだけ（文脈には何も置かない）** | **0.79** | **0.92** | **17 / 24** |
| 定義文とベクトルの両方 | 0.79 | 0.67 | 11 / 24 |

選択肢の順序を入れ替えても両方正答する率と、正答と誤答のロジット差の平均:

| 条件 | G2c 順序に頑健 | G2k 順序に頑健 | G2c ロジット差 | G2k ロジット差 |
|---|---|---|---|---|
| 定義文と適用例4問を文脈に置く | 0.50 | 0.58 | +1.70 | +2.24 |
| ベクトルだけ | 0.67 | 0.79 | +4.96 | +7.10 |

- **語の位置に加える1本のベクトルが、概念の境界を担える。** 未見の事例で、衝突する設問と衝突しない設問の両方が上がった。定義文だけで学習した版のような反転は起きていない。
- **同じ教師情報を文章で渡すより、ベクトルの方がよい。** 正答率の差は小さいが、選択肢の順序への頑健さと確信の強さで差が大きい。
- **定義文とベクトルを併用すると下がる。** 定義文の中に現れる語にもベクトルが加わることが原因と考えられる（未検証）。
- 24概念中4概念（国内、大人、大口注文、無料）は学習の損失が下がりきらなかった。数値の境界を持つ概念が多い。

### 限界

- 学習と評価の設問形式が同じ（「〜に当たるか」の二択）。形式への適合と概念の獲得を区別できていない。
- 1概念ずつ評価している。多数のベクトルを同時に入れたときの干渉は測っていない。
- 正本（定義文）だけからはコンパイルできていない。適用例という追加の教師が要る。

## E3b: 概念ベクトルの転移・干渉・局所性

```
python e3b_transfer.py --model Qwen/Qwen2.5-1.5B-Instruct --layer 8 \
    --vectors results/e3_Qwen2.5-1.5B-Instruct_L8_qa.pt
```

適用例で学習したベクトルを、そのまま別の条件で評価した。数値は正答率、括弧内は選択肢の順序を入れ替えても両方正答する率。

### 形式の転移

| 設問形式 | 群 | 何もなし | 文章（定義文＋適用例4問） | ベクトル |
|---|---|---|---|---|
| 学習時と同じ（はい/いいえ） | G2c 衝突 | 0.38 (0.29) | 0.79 (0.50) | 0.79 (0.67) |
| | G2k 非衝突 | 0.75 (0.50) | 0.71 (0.58) | 0.92 (0.79) |
| 空欄補充（当たる/当たらない） | G2c 衝突 | 0.42 (0.00) | 0.71 (0.62) | 0.79 (0.58) |
| | G2k 非衝突 | 0.71 (0.17) | 0.67 (0.58) | 0.75 (0.62) |
| 正誤判定（正しい/誤り） | G2c 衝突 | 0.50 (0.21) | 0.58 (0.50) | 0.79 (0.62) |
| | G2k 非衝突 | 0.67 (0.62) | 0.75 (0.75) | 0.71 (0.58) |

- **衝突する設問への効果は、形式を変えても保たれる（3形式とも 0.79）。** 形式への適合だけでは説明できない。
- **衝突しない設問での上積みは、形式を変えると消える（0.92 → 0.75、0.71）。** 何もなしの水準に戻るだけで、壊れてはいない。
- 文章で渡す方式は、形式によって衝突する設問の正答率が 0.58〜0.79 と揺れる。

### 干渉と局所性

| 測ったもの | 1概念ずつ | 24概念を同時に |
|---|---|---|
| G2c 衝突（学習時と同じ形式） | 0.79 | 0.79 |
| G2k 非衝突（学習時と同じ形式） | 0.92 | 0.88 |
| G2c 衝突（空欄補充 / 正誤判定） | 0.79 / 0.79 | 0.79 / 0.79 |
| G2k 非衝突（空欄補充 / 正誤判定） | 0.75 / 0.71 | 0.71 / 0.67 |

| 無関係な設問（G1、19問） | 何もなし | 24概念を同時に |
|---|---|---|
| 正答率 | 1.00 | 1.00 |
| ロジット差の平均 | +5.11 | +4.41 |

- **24概念を同時に入れても、ほぼ劣化しない。** ベクトルは語が現れた位置にしか加わらないため、干渉は語が重なる場合（「週に二日」の「週」など）に限られる。
- **無関係な設問の答えは変わらない。** 確信はわずかに下がる。

### 限界

- 24概念までしか試していない。数百の規模での干渉は未確認。
- 二択の1トークンだけを見ている。文章を生成させたときの振る舞いは測っていない。

## E3c: 文章を生成させたときの答え

```
python e3c_generation.py --model Qwen/Qwen2.5-1.5B-Instruct --layer 8 \
    --vectors results/e3_Qwen2.5-1.5B-Instruct_L8_qa.pt
```

選択肢を示さず、「はい」か「いいえ」で答えて理由を一文で述べるよう求めた。出力の冒頭で判定した。ベクトルは入力の語の位置にだけ加え、生成中の語には加えていない。

| 条件 | G2c 衝突する設問 | G2k 衝突しない設問 | 両方に正答した概念数 |
|---|---|---|---|
| 何もなし | 0.38 | 0.71 | 2 / 24 |
| 文章（定義文＋適用例4問） | 0.62 | 0.67 | 9 / 24 |
| ベクトルだけ | 0.67 | 0.88 | 13 / 24 |

- **ベクトルの効果は、自由に答えさせた場合にも現れる。** 二択のときより下がる（衝突 0.79 → 0.67）が、文章で渡す方式を上回る。
- **ベクトルは判定を動かすが、理由は説明できない。** 出力を読むと、答えは定義側に動いても、理由が定義と無関係だったり、答えと矛盾したりする例がある（「はい。…社員には該当しないと言える。」）。文章で定義を渡した場合は、理由に定義を引用できている。理由の質は目視での観察で、数値化していない。
- ベクトルは適用例の答えだけを教師にしているので、定義の内容を言葉にする力を持たないのは当然とも言える。説明が要る用途では、ベクトルだけでは足りない。

## E4: 修飾の合成

```
python e4_modifier_composition.py --model Qwen/Qwen2.5-1.5B-Instruct --layer 8
```

修飾を表す語（甲種/乙種、青/赤、一類/二類）ごとに1本のベクトルを持ち、2つの上位概念の上の適用例8問で学習した。評価は、学習に使っていない別の2つの上位概念の上で行った。数値は正答率、括弧内は選択肢の順序を入れ替えても両方正答する率。

| 修飾の組 | 学習の損失 | 学習した上位概念（ベクトル） | 学習していない上位概念：何もなし | 文章（修飾の定義文） | ベクトル |
|---|---|---|---|---|---|
| 一類/二類 | 1.03 → 0.08 | 1.00 (1.00) | 0.50 (0.00) | 0.50 (0.00) | 0.88 (0.75) |
| 甲種/乙種 | 0.96 → 0.68 | 0.50 (0.50) | 0.50 (0.12) | 1.00 (0.50) | 0.50 (0.38) |
| 青/赤 | 1.35 → 0.67 | 0.75 (0.12) | 0.50 (0.25) | 0.88 (0.38) | 0.62 (0.50) |

- **結論は出ていない。** 3組のうち2組は学習が収束しなかった（損失 0.68 前後は、二択で当て推量をしたときの値）。学習した上位概念の上ですら区別できていないので、合成の可否を判定できない。
- **収束した1組（一類/二類）では、学習していない上位概念でも通用した（0.88）。** 合成が成り立つ可能性を示すが、1組だけでは根拠として弱い。
- 新しい語の修飾は、文章の定義だけでもおおむね従う（0.50〜1.00）。E1 の「新しい語は文章で従う」と合う。ただし選択肢の順序への頑健さは低い。
- 次の手: 学習の反復回数と学習率を見直して、収束しなかった2組をやり直す。

## E5: 言い換え（文章の側で再定義に従わせる手段）

```
python e5_paraphrase.py --model Qwen/Qwen2.5-1.5B-Instruct
```

一般語の再定義について、ベクトルを使わない手段を比べた。数値は正答率、括弧内は選択肢の順序を入れ替えても両方正答する率。

| 条件 | 内容 | G2c 衝突する設問 | G2k 衝突しない設問 | 両方に正答した概念数 |
|---|---|---|---|---|
| near | 定義文を直前に置く（基準） | 0.58 (0.42) | 0.75 (0.75) | 10 / 24 |
| rename_semi | 元の語が見える新しい語に改名（社員 → P社員） | 0.58 (0.42) | 0.79 (0.71) | 11 / 24 |
| rename_opaque | 元の語が見えない新しい語に改名（社員 → 用語08） | 0.58 (0.50) | 0.75 (0.62) | 9 / 24 |
| inline | 設問中の語の直後に定義を展開 | 0.46 (0.17) | 0.83 (0.54) | 8 / 24 |
| near+inline | 定義文を直前に置き、設問中でも展開 | 0.42 (0.33) | 0.88 (0.71) | 9 / 24 |

- **改名しても変わらない。** 元の語が完全に見えない語（用語08）に替えても、衝突する設問は 0.58 のまま。
- **したがって、E1 の失敗は「語が元から持つ意味に押し負ける」だけでは説明できない。** 語を消しても同じだけ間違えるので、原因は語ではなく、事例の側にある。「アルバイトは雇用契約者の全員に含まれる」のように、定義を事例に当てはめる推論そのものを、このモデルが誤っていると読むのが自然である。
- **E1 の解釈を改める必要がある。** 「文章での注入は元の意味に押し負ける」という仮説は、この結果では支持されない。小さいモデルの推論力の不足と、元の意味との衝突とを、まだ切り分けられていない。
- 設問中に定義を展開すると、衝突する設問はかえって下がる。
- 次の手: より大きいモデルで E1 と E5 を回し、(a) 定義文だけで従えるようになるか、(b) 改名の効果が現れるか、を見る。

## より大きいモデルでの E1 と E5（Qwen3-4B）

```
python e1_context_injection.py --model Qwen/Qwen3-4B --dtype bfloat16
python e5_paraphrase.py --model Qwen/Qwen3-4B --dtype bfloat16
```

設問と条件は 1.5B のときと同じ。数値は正答率、括弧内は選択肢の順序を入れ替えても両方正答する率。

### E1: 定義を文章として注入

| 群 | 問数 | none | near | glossary | far-500 | far-2000 |
|---|---|---|---|---|---|---|
| G1 一般の類義語・同音語 | 19 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| G2c 再定義。衝突する設問 | 24 | 0.38 (0.38) | 0.75 (0.75) | 0.46 (0.38) | 0.46 (0.42) | 0.50 (0.42) |
| G2k 再定義。衝突しない設問 | 24 | 0.83 (0.79) | 0.83 (0.83) | 0.79 (0.71) | 0.79 (0.75) | 0.79 (0.75) |
| G3 分化した兄弟概念（新しい語） | 8 | 0.38 (0.00) | 1.00 (1.00) | 1.00 (0.88) | 1.00 (0.88) | 1.00 (0.88) |
| G4 置換された用語（新しい語） | 4 | 0.50 (0.25) | 1.00 (1.00) | 1.00 (1.00) | 1.00 (1.00) | 1.00 (1.00) |

### E5: 言い換え

| 条件 | G2c 衝突する設問 | G2k 衝突しない設問 | 両方に正答した概念数 |
|---|---|---|---|
| near（定義文を直前に置く） | 0.75 (0.75) | 0.83 (0.83) | 14 / 24 |
| rename_semi（社員 → P社員） | 0.79 (0.79) | 0.92 (0.88) | 17 / 24 |
| rename_opaque（社員 → 用語08） | 0.92 (0.92) | 0.79 (0.75) | 17 / 24 |
| inline（設問中に定義を展開） | 0.67 (0.62) | 0.88 (0.83) | 14 / 24 |
| near+inline | 0.83 (0.79) | 0.88 (0.88) | 17 / 24 |

### 読み取れること

- **元の意味との衝突は実在する。** 同じ用語集の中で、新しい語（G3・G4）は 1.00 で従うのに、一般語の再定義（G2c）は 0.46 で、定義なし（0.38）とほぼ同じ。用語集を読めていないのではなく、再定義だけが無視されている。
- **再定義は、定義文が直前にあっても 0.75 にとどまる。** 新しい語は同じ条件で 1.00。
- **改名は効く。** 元の語が見えない語に替えると、衝突する設問は 0.75 → 0.92 に上がる。元の語が見える改名（P社員）は 0.79 で、効果が小さい。
- **1.5B の結果との関係。** 1.5B では改名しても 0.58 のままだった。これは、定義を事例に当てはめる処理そのものが 1.5B には重く、衝突の有無が結果に表れなかったためと読める。1.5B での E1 の数値は、衝突の証拠としては使えない。衝突の証拠は 4B の結果による。
- 選択肢の順序への頑健さは、4B では正答率とほぼ一致する。1.5B で見られた位置への偏りは小さい。

### 未確認

- 改名した語を用語集に埋めた場合。新しい語（G3・G4）は用語集でも従うので、改名で用語集の問題も解ける可能性があるが、測っていない。
- 4B での概念ベクトル。

## E6: 使い方をまたぐ転移（「定義する」側）

```
python e6_cross_use.py --model Qwen/Qwen2.5-1.5B-Instruct --layer 8 \
    --vectors none results/e3_..._defonly.pt results/e3_..._qa.pt
```

1つの使い方で学習したベクトルが、別の使い方も変えるかを測る。「定義する」側の指標は2つ。

- **定義の二択**: 「語」の定義として、プロジェクトの定義と一般の定義のどちらを選ぶか。選択肢は定義文そのものではなく言い換え（`data/definition_choice_ja.json`）。
- **定義文の出しやすさ**: 「語の定義を答えよ」に対してプロジェクトの定義文を出力するときの、1トークンあたりの負の対数尤度。小さいほど出しやすい。

### 結果（Qwen2.5-1.5B-Instruct、第8層、24概念）

| ベクトルの教師 | 定義の二択：プロジェクトの定義を選ぶ率 | ロジット差の平均 | 定義文の出しやすさ | 適用する（衝突 / 非衝突） |
|---|---|---|---|---|
| なし | 0.12 | −2.57 | 2.70 | 0.38 / 0.75 |
| 定義文の暗唱 | 0.46 | −0.25 | 0.01 | 0.67 / 0.33 |
| 適用例 | 0.33 | +0.08 | 3.01 | 0.79 / 0.92 |

- **定義文の暗唱で学習したベクトルは、自分が暗唱する定義の言い換えを選べない。** 定義文は一字一句出せる（0.01）のに、言い換えの二択は偶然の水準（ロジット差 −0.25）。文字列を覚えただけで、内容は入っていない。
- **適用例で学習したベクトルは、定義には転移しない。** 適用は変えるが、定義の二択は偶然の水準で、定義文はかえって出しにくくなる。
- **どちらのベクトルも、一般の意味への傾きは消している**（−2.57 → 0 付近）。元の意味を弱めてはいるが、新しい意味を「定義する」使い方に入れてはいない。
- 結論: 第8層の1本のベクトルは、教えた使い方だけを変える。使い方が共有する推論には届いていない。
- 次の手: 定義と適用の両方を教師にして学習し（`run_layers.sh`）、層を変えて、両方が揃って変わる位置を探す。

## E7: 定義が効かなくなる原因の切り分け（Qwen3-4B）

```
python e7_dilution.py --model Qwen/Qwen3-4B --dtype bfloat16
```

E1 では「定義文を直前に置く」と「用語集に入れる」の間で、定義の数・設問からの距離・置き場所が同時に変わっていた。1つずつ動かした。定義はすべてシステムプロンプトに置く。数値は正答率。

| 条件 | 内容 | 再定義で衝突する設問（24問） | 新しい語（12問） |
|---|---|---|---|
| （E1）near | 関係する定義だけを、利用者の発話の中で設問の直前に置く | 0.75 | 1.00 |
| sys1 | 関係する定義だけをシステムプロンプトに置く | 0.67 | 1.00 |
| sys1-far500 | 上に加えて、無関係な文章 約500トークン | 0.75 | 1.00 |
| sys1-far2000 | 上に加えて、無関係な文章 約2000トークン | 0.71 | 1.00 |
| gl5 | 関係する定義を含む5定義（順序は無作為） | 0.71 | 1.00 |
| gl15 | 関係する定義を含む15定義（順序は無作為） | 0.71 | 1.00 |
| gl55-first | 全55定義。関係する定義を先頭に置く | 0.71 | 1.00 |
| gl55-last | 全55定義。関係する定義を末尾に置く | 0.54 | 1.00 |
| （E1）glossary | 全55定義。関係する定義は中ほどから後ろ | 0.46 | 1.00 |

- **文脈の長さは原因ではない。** 無関係な文章を2000トークン足しても（0.71）、55定義の用語集でも関係する定義が先頭なら（0.71）、落ちない。
- **設問からの距離も原因ではない。** 設問に最も近い末尾に置いた場合（0.54）の方が、最も遠い先頭に置いた場合（0.71）より低い。
- **効いているのは、関係する定義の前に他の定義がどれだけ並んでいるかである。** 多数の定義のあとに置かれた再定義が無視される。5〜15定義の規模では落ちない。
- **新しい語は、どの条件でも 1.00。** 落ちるのは、元の意味と競合する定義だけ。
- 1問の差が 0.04 に当たる規模なので、0.67〜0.75 の間の差は意味のある差とは言えない。0.71 と 0.54、0.46 の差（4〜6問）が、ここで読める差である。

### 未確認

- 前に並ぶものが「他の定義」であることが効いているのか、単に文脈の深い位置にあることが効いているのか。無関係な文章のあとに定義を置く条件で区別できる。
- 用語集の中での位置を細かく動かしたときの推移。
- 数千トークンを超える規模。

### 結果: 定義と適用の両方を教師にした場合（第8層）

```
./run_layers.sh 8
```

| ベクトルの教師 | 定義の二択：プロジェクトの定義を選ぶ率 | 定義文の出しやすさ | 適用する（衝突 / 非衝突） | 定義文と併用したときの適用（衝突 / 非衝突） |
|---|---|---|---|---|
| なし | 0.12 | 2.70 | 0.38 / 0.75 | 0.58 / 0.75（定義文だけ） |
| 定義文の暗唱 | 0.46 | 0.01 | 0.67 / 0.33 | 0.67 / 0.25 |
| 適用例 | 0.33 | 3.01 | 0.79 / 0.92 | 0.79 / 0.67 |
| 定義文の暗唱＋適用例 | 0.54 | 0.63 | 0.79 / 0.92 | 0.88 / 0.83 |
| （参照）ベクトルなしで、定義文を文脈に置く | 0.96 | — | 0.58 / 0.75 | — |

- **両方を教えても、互いに邪魔はしない。** 適用は適用例だけのときと同じ（0.79 / 0.92）で、定義文もおおむね出せる（0.63）。
- **文章との併用で下がる問題が解消した。** 適用例だけのベクトルは定義文と併用すると非衝突が 0.67 に落ちたが、両方を教えたベクトルは 0.88 / 0.83 で、今回の全条件の中で最もよい。
- **定義の言い換えは、依然として選べない（0.54、偶然は 0.50）。** 定義文を文脈に置けば、同じモデルが 0.96 で選べる。課題としては解けるものなので、ベクトルが定義の内容を運んでいないことになる。
- 結論: 教えた使い方（定義文の暗唱、適用）は1本のベクトルに同居できる。しかし教えていない使い方（定義の言い換えの理解）には広がらない。第8層の1本のベクトルは、使い方が共有する推論には届いていない。

### E7 の続き: 「前に並ぶ定義」か「文脈の深さ」か

```
python e7_dilution.py --model Qwen/Qwen3-4B --dtype bfloat16 --set b --groups G2c
```

再定義で衝突する設問（24問）だけを対象にした。数値は正答率。

| 条件 | 関係する定義の前にあるもの | 正答率 |
|---|---|---|
| sys1（再掲） | なし | 0.67 |
| fill500-def | 無関係な文章 約500トークン | 0.67 |
| fill2000-def | 無関係な文章 約2000トークン | 0.67 |
| gl55-first（再掲） | なし（後ろに54定義） | 0.71 |
| gl55-pos14 | 14定義 | 0.62 |
| gl55-pos27 | 27定義 | 0.54 |
| gl55-pos41 | 41定義 | 0.50 |
| gl55-last（再掲） | 54定義 | 0.54 |
| pre-ordinary19 | 一般の意味どおりの定義19個 | 0.54 |
| pre-redef23 | 他の再定義23個 | 0.58 |

- **原因は文脈の深さではなく、前に並ぶ定義である。** 無関係な文章を2000トークン前に置いても落ちない（0.67）。定義が前に並ぶと落ちる。
- **前に並ぶ定義が増えるほど下がり、20〜30個で底に着く。** 0個で 0.71、14個で 0.62、27個以上で 0.50〜0.54。
- **前に並ぶ定義の種類は問わない。** 一般の意味どおりの定義19個でも（0.54）、他の再定義23個でも（0.58）、同じ程度に落ちる。
- 解釈: 同じ形式の項目が並ぶと、関係する定義を引き当てる処理が弱まり、モデルは語が元から持つ意味に戻る。新しい語には戻る先がないので、影響を受けない。この解釈は未検証。

## 再集計: 再定義の型による違い

既存の結果を、再定義の型で分けて集計し直した（新しい実験は行っていない）。

- **規則型（12概念）**: 数値のしきい値や暦の計算で境界が決まるもの。営業日、新規、週、午前、大口注文、遅延、未成年、平日、無料、夜間、大人、都市部。
- **付け替え型（12概念）**: 含める対象の範囲を広げる、または狭めるもの。顧客、在庫、完了、売上、社員、管理者、国内、果物、魚類、家族、赤字、欠席。

数値は「衝突する設問の正答率 / 衝突しない設問の正答率 / 両方に正答した概念数」。

| 条件 | 規則型 | 付け替え型 |
|---|---|---|
| 1.5B なし | 0.17 / 0.83 / 1 | 0.58 / 0.67 / 4 |
| 1.5B 定義文を直前に置く | 0.33 / 0.67 / 1 | 0.83 / 0.83 / 9 |
| 1.5B 定義文＋適用例4問 | 0.58 / 0.67 / 3 | 1.00 / 0.75 / 9 |
| 1.5B ベクトル（適用例） | 0.67 / 0.92 / 7 | 0.92 / 0.92 / 10 |
| 1.5B ベクトル（定義＋適用例） | 0.67 / 0.83 / 7 | 0.92 / 1.00 / 11 |
| 4B なし | 0.42 / 0.83 / 3 | 0.33 / 0.83 / 2 |
| 4B 定義文を直前に置く | 0.75 / 0.83 / 7 | 0.75 / 0.83 / 7 |
| 4B 見えない語に改名 | 0.83 / 0.83 / 8 | 1.00 / 0.75 / 9 |

適用例で学習したベクトルの、学習の損失の平均: 規則型 0.25、付け替え型 0.05。

- **1.5B が文章の定義に従えなかったのは、ほぼ規則型に限られる。** 付け替え型は、定義文を直前に置くだけで 12概念中9概念が正答する。規則型は1概念。1.5B の「定義を事例に当てはめられない」は、数値や暦の照合ができないことだった。
- **ベクトルは付け替え型でほぼ成功し（10〜11概念）、規則型では半分強にとどまる（7概念）。** 学習の損失も規則型の方が高い。足し込むだけのベクトルは、モデルが既に持っている別の概念へ語を付け替えることは得意だが、新しい規則を作ることは苦手、という予想と合う。ただし規則型でも文章（1〜3概念）より大きく上回っており、「できない」わけではない。
- **4B では、文章での型の差は消える**（どちらも7概念）。改名は付け替え型でより効く。
- 注意: 型の分類は、結果の一部を見たあとで行った。分類の基準（数値・暦か、範囲の伸縮か）は機械的だが、事前に決めた分類ではない。
